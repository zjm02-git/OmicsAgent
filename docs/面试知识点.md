## 一、项目一句话总结（开场必背）

> 我用 LangGraph 把「差异表达分析 + 通路富集」编排成 8 个节点的图：LLM 负责理解需求和解读结果，Python 负责质检和统计计算，中间用条件边做路由、用检查点做断点续跑、用 interrupt 做人工确认、用 Store 做长期记忆，最后自动产出一份带解读的分析报告。

## 二、LangGraph 核心概念（速记）

| 概念 | 一句话解释 | 生活比喻 |
| --- | --- | --- |
| **State（状态）** | 整个流程共享的"记事本"，节点往里写、往下读 | 流水线上传递的"工单" |
| **Node（节点）** | 一个干具体活儿的函数 | 流水线上的一个工位 |
| **Edge（边）** | 节点之间的连线，决定执行顺序 | 工位之间的传送带 |
| **条件边** | 会"看情况拐弯"的边 | 传送带上的分拣口，合格往左、不合格往右 |
| **Checkpointer** | 每个节点跑完自动存档 | 游戏存档点，死了从这里接着打 |
| **interrupt（HITL）** | 节点跑一半挂起，等人批准/取消再继续 | 流水线上的"暂停键"，关键步骤要人点头 |
| **Store（长期记忆）** | 跨任务、跨重启存"这个用户偏好什么" | 一本按用户分页的持久笔记本 |

## 三、两个核心算法（这是岗位硬知识，必背）

### 算法 1：差异表达分析（判断"哪些基因变了"）

对每个基因看三个数：

1. **log2FC（fold change，倍数变化）**
   - 表达量差了多少倍，取 log2 是为了让"上调 2 倍"和"下调 2 倍"在数值上对称（+1 和 -1）。
   - 我的项目里阈值是 |log2FC| > 1，也就是差 2 倍以上才算。

2. **p 值（Welch t 检验）**
   - 这个差异"是不是碰巧出现的"概率。p 越小越不像碰巧。
   - 我用的是 Welch t 检验（不假设两组方差相等，更稳健）。

3. **FDR（多重检验校正）**
   - **为什么需要它**：一次比较成百上千个基因，如果每个都用 p<0.05，会有一大堆假阳性（比如 1000 个基因会有约 50 个碰巧显著）。
   - FDR 就是把"假阳性比例"控制住。我用 BH 校正（Benjamini-Hochberg）。

> 一句话：**log2FC 看"差得多不多"，p/FDR 看"差得可不可信"**，两个都满足才叫显著。

### 算法 2：通路富集分析（判断"这些基因扎堆在哪些功能"）

核心是**超几何检验**，生活比喻是"**抽球**"：

- 袋子里有 N 个球（所有基因），其中 K 个是红球（属于某通路的基因）。
- 你随手抽出 n 个球（显著基因），里面恰好有 k 个红球。
- 如果 k 比"瞎抽该有的数量"多得多 → 显著基因**偏爱**这个通路 → **富集**。

> 一句话：**超几何检验回答"显著基因是不是扎堆在某个通路"，扎堆程度远超随机就叫富集。** 同样要做 BH 校正，否则通路一多假阳性跟着多。

## 四、八个节点「做什么 + 为什么」

| 节点 | 做什么 | 为什么 | 谁干 |
| --- | --- | --- | --- |
| ① parse_intent | LLM 结构化输出，判断分析类型 | 用户说人话，机器要"确定的值"才能路由 | LLM |
| ② load_qc | 读数据 + 质检 + 读记忆里的阈值 | 垃圾进垃圾出，先卡一道；阈值记住上次选择 | Python |
| ③ human_review | interrupt 暂停，等人工批准/取消 | 关键步骤要人把关，不能闷头跑到底 | 系统 |
| ④ diff_analysis | t 检验 + log2FC + BH 校正 | 核心计算，必须真算，不能靠 LLM 编 | Python |
| ⑤ enrichment | 超几何检验 + BH 校正 | 光知道"哪些基因变了"不够，还要知道"变了意味着什么" | Python |
| ⑥ interpret | LLM 解读基因列表 + 富集通路 | 数字要翻译成人话才有价值 | LLM |
| ⑦ save_memory | 把阈值偏好写回长期记忆 | 下次自动复用，少填参数 | 系统 |
| ⑧ report | 汇总成 Markdown 报告 | 交付物要完整可追溯 | Python |

**核心分工思想**（面试高频点）：
> **LLM 干"懂"的活，Python 干"算"的活，系统干"把关 + 记忆"的活，各用所长。** 不能让 LLM 去做统计（会算错/编造），也不能让代码去写自然语言解读。

## 五、结构化输出是什么、为什么用

- **是什么**：`with_structured_output` 让 LLM 不是自由写文字，而是填一个固定格式（比如必须输出 `differential` 或 `other` 之一）。
- **为什么用**：路由必须靠"确定的值"。如果让 LLM 自由回答"你想做什么分析"，它可能写一长串，代码没法判断走哪条路。
- **比喻**：自由文本像"随便说说"，结构化输出像"填表格选择题"，机器好处理。

## 六、高频面试题（自测用）

**Q1：LangGraph 和 LangChain 有什么区别？**
A：LangChain 适合"一条直线"的任务（检索→生成）；LangGraph 适合"一张图"——有分支、有循环、有状态、要断点续跑，还支持人工确认和长期记忆。我这个项目有质检分叉、有状态流转、要人工确认，所以用 LangGraph。

**Q2：为什么不做成"一条脚本跑到底"，要拆成节点+图？**
A：三个好处：① 每个节点职责单一，好维护好测试；② 能加条件边，数据不合格自动走失败分支；③ 每个节点跑完有检查点，中断了能接着跑。

**Q3：质检为什么放在分析前面？**
A：数据不合格（缺列、样本太少、缺失值多），后面分析全白算。先卡一道，避免"垃圾进垃圾出"。

**Q4：FDR 是干嘛的？为什么不能只看 p 值？**
A：一次比几千个基因，p<0.05 会大量假阳性。FDR 控制"假阳性占所有阳性的比例"，更严格。

**Q5：如果数据量变成几十万个基因，哪里会慢？怎么优化？**
A：逐基因 for 循环会慢。可以向量化（numpy 矩阵运算一次算所有基因），或者并行。这也是为什么用 numpy 而不是纯 Python 循环。（进阶加分点）

**Q6：检查点（checkpoint）能解决什么实际问题？**
A：真实分析一次可能跑很久，跑到一半断了，检查点让你从断点接着跑，不用从头再来。用 thread_id 区分不同分析任务。

**Q7：通路富集分析是干嘛的？超几何检验怎么理解？**
A：找出"显著基因是不是扎堆在某些功能通路上"。超几何检验就是"抽球"：袋子里 N 个球 K 个红球，抽 n 个抽到 k 个红球，k 比随机预期多很多就说明"偏爱"这个通路，即富集。

**Q8：为什么富集分析也要做多重检验校正？**
A：一次查几十上百个通路，p<0.05 也会有一堆假阳性，和差异分析同理，要用 BH 校正控制 FDR。

**Q9：Human-in-the-loop（HITL）是什么？为什么需要？**
A：Agent 在关键步骤（比如质检后）用 `interrupt` 挂起，把中间结果抛给人确认，批准才继续、取消就终止。目的是不让 Agent 闷头跑到底——分析这种严肃场景，关键决策要人把关，错一步后面全错。

**Q10：长期记忆和状态（State）有什么区别？**
A：State 是一次任务内共享的"记事本"，任务结束就没了；Store 是跨任务、跨重启的"持久笔记本"，用来存"这个用户上次偏好什么阈值"这类要长期记住的东西。实现上 State 走 checkpointer，长期记忆走 Store（配 Postgres 落到数据库）。

## 九、代码追问速记（面试官让你"打开代码讲讲"时用）

> 上面八节是"讲道理"，这一节是"讲代码"。面试官可能现场指着代码问，这些要能对答。

### 1. State 里存了什么？（state.py）

用 `TypedDict` 定义，`total=False` 表示字段是"走到哪一步填哪一步"，不是一开始全有：

| 阶段 | 字段 | 含义 |
| --- | --- | --- |
| 输入 | `user_request` / `dataset_path` / `user_id` | 用户需求 / 数据目录 / 区分研究者 |
| ①解析 | `analysis_type` | 判断出要做什么分析（differential/other） |
| ②质检 | `qc_passed` / `qc_report` / `group_a` / `group_b` | 过没过 / 质检报告 / 两组名字 |
| 参数 | `fc_threshold` / `fdr_threshold` / `prefs_from_memory` | 阈值 / 是否来自长期记忆 |
| ④差异 | `diff_summary` / `significant_count` / `sig_genes_up` / `sig_genes_down` | 摘要 / 显著数 / 上·下调基因列表 |
| ⑤富集 | `enrichment_summary` | 富集通路摘要 |
| ⑥⑧ | `interpretation` / `final_report` | LLM 解读 / 最终报告 |

### 2. interrupt 怎么用？怎么恢复？（human_review_node）

- 节点里 `decision = interrupt({...})` 挂起，把质检结果抛给人；**返回值就是外部 resume 回来的值**。
- 外部恢复：`graph.invoke(Command(resume={"approved": True}), config)`。
- 节点判断 `decision.get("approved") is False` → 取消，把 `qc_passed` 置 False，走报告分支。

### 3. Checkpointer 怎么配？thread_id 干嘛用？（graph.py）

- `builder.compile(checkpointer=..., store=...)` 挂上检查点和长期记忆。
- `config={"configurable": {"thread_id": "xxx"}}` 区分不同分析任务，各存各的档、互不干扰。
- 默认内存版（InMemorySaver/InMemoryStore），设 `USE_POSTGRES=true` 切 Postgres 版，重启不丢。

### 4. 三个条件边怎么路由？（graph.py 的三个 route 函数）

| 位置 | 判断 | 走法 |
| --- | --- | --- |
| parse_intent 后 | `analysis_type == "differential"` | 是 → load_qc；否 → report |
| load_qc 后 | `qc_passed` | 真 → human_review；假 → report |
| human_review 后 | `qc_passed`（批准） | 真 → diff_analysis；假（取消）→ report |

### 5. 质检具体查哪 5 项？（load_qc_node）

1. 两个 csv（expression / metadata）**文件在不在**；
2. metadata 里有没有 **condition 分组列**；
3. 是否**恰好 2 组**；
4. 每组**样本数 ≥ 2**（t 检验才成立）；
5. **缺失值比例 ≤ 10%**。

任一项不过 → `qc_passed=False` + 写清原因的 `qc_report`，直接走失败分支，不硬算。

### 6. 长期记忆怎么读写？（load_qc / save_memory）

- 存储结构：命名空间 `("omics",)` + `user_id` + key `"preferences"`，即"按研究者分页"。
- 读：`runtime.store.get((*MEMORY_NS, user_id), PREFS_KEY)`；写：`runtime.store.put(...)`，存 fc/fdr 阈值和两组名。
- **兜底**：读不到用默认阈值、写失败 try/except 吞掉，都不影响主流程。

### 7. 两个"降级"设计（体现工程稳健性）

- **富集分析**：缺 `gene_ontology.csv` 就返回"跳过富集分析"，不阻断整条流水线。
- **长期记忆**：读不到/写失败都不报错，用默认阈值继续跑。

### 8. report 节点怎么处理三种情况？（report_node）

1. `analysis_type == "other"` → 出"暂不支持该分析类型"；
2. `qc_passed == False`（质检失败或用户取消）→ 出"质检未通过"报告；
3. 正常 → 完整报告（质检 + 差异 + 富集 + 解读），参数标注"**默认 / 来自长期记忆**"。
