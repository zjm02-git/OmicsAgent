> 这份文档把整个项目从「做什么」到「为什么这么做」讲透，全程用大白话和比喻。
> 目标：面试时你能**从头到尾讲清楚**，被追问也不慌。
> 配合 `面试知识点.md` 一起看，一个是"理解"，一个是"要背的答案"。

## 一、这个项目到底在做什么

**一句话**：生物信息里有个常见活——拿两组样本（比如"患病组"和"正常组"）的基因表达数据，找出哪些基因表达不一样了，再找出这些不一样的基因都聚集在哪些"功能通路"上，最后写一段人话解释"这些变化说明身体发生了什么"。

传统做法：每一步都要人手动敲命令、换工具、盯结果，特别琐碎。

**这个项目**：用 LangGraph 把这一整条流程做成一个"自动流水线"，你只需要说一句"帮我找差异表达基因并解读"，它就自动走完全部步骤，交给你一份带解读的报告。

**生活比喻**：就像做菜——买菜（加载数据）→ 洗菜（质检）→ 让你看一眼"这样洗行不行"（人工确认）→ 炒菜（差异分析）→ 摆盘（富集分析）→ 试味讲解（解读）→ 记下你的口味下次照着做（长期记忆）→ 上菜（报告）。以前每一步都得你自己动手，现在你喊一声"做道菜"，厨房自动做完、还记着你的口味。

## 二、为什么用 LangGraph，而不是 LangChain

- **LangChain** 适合"一条直线"的任务，比如 RAG：检索 → 生成，一步到位，没岔路。
- **这个项目是一张"图"**，因为：
  - 有**分支**：质检不合格要走"失败报告"，合格才继续分析；
  - 有**状态**：上一步的结果要传给下一步；
  - 有**中断恢复**：跑一半断了，能从断点接着跑；
  - 有**人工确认**：关键步骤要停下来等人点头（HITL）；
  - 有**记忆**：要记住不同用户的偏好，下次自动用（长期记忆）；
  - 有**扩展需求**：以后加"生存分析"，就是往图里加节点、加岔路。

**LangGraph 的核心思想**：把程序画成一张"节点 + 边"的图，数据（状态）在节点之间流动。

## 三、核心概念，逐个用大白话讲

### 1. State（状态）＝ 共享记事本
整个流程有一本"记事本"，每个节点从里面读自己需要的信息，干完活把结果写回去，下一个节点接着读。数据放 State、逻辑放节点，两者分开，加节点改节点都不会乱。

### 2. Node（节点）＝ 流水线上的一个工位
一个节点就是一个函数，只干一件事。比如"质检"这个工位只管检查数据合不合格，别的不管。

### 3. Edge（边）＝ 工位之间的传送带
决定谁干完轮到谁。普通边是"直着走"，条件边是"看情况拐弯"。

### 4. 条件边（路由）＝ 传送带上的分拣口
`load_qc` 之后有个分拣口：质检合格往左（继续分析），不合格往右（直接出失败报告）。让流程自己判断，而不是数据坏了还硬算或崩溃。

### 5. Checkpointer（检查点）＝ 游戏存档
每个节点跑完自动存个档。真实分析一次可能跑几十分钟，跑到一半断了，从存档接着跑，不用重头再来。用 `thread_id` 区分不同任务，各存各的档。

### 6. 结构化输出 ＝ 让 LLM 做选择题而不是简答题
`with_structured_output` 让 LLM 不是自由写文字，而是填固定格式（比如只能输出 `differential` 或 `other`）。因为路由要靠"确定的值"，自由文本没法判断走哪条路。

### 7. interrupt / HITL ＝ 流水线上按了个"暂停键"
节点跑一半能 `interrupt(value)` 挂起，把中间结果抛给用户看，等用户批准或取消后再继续。这就是 **Human-in-the-loop（人在环中）**：不让 Agent 闷头跑到底，关键决策点要人把关。

### 8. Store（长期记忆）＝ 一本按"用户"分页的持久笔记本
和 State（一次任务内的记事本）不同，Store 跨任务、跨重启还在，用来存"这个用户上次偏好什么阈值"这类要长期记住的东西。配 Postgres 就落到数据库，配内存就只在本次会话。

### 9. 回溯（时间旅行）＝ 游戏读档，回到过去改选择
因为每个节点跑完都存档（检查点），所以不只"接着最后一步跑"，还能**回到任意历史存档**：用 get_state_history 列出所有存档，用 update_state 把新参数写进某个旧存档，再从那里重跑。用途：跑完发现阈值太松/太严，不用从头跑，回到"质检之后"改个阈值接着跑，前面的读数据、质检都不重算。生活比喻：游戏里 SL 大法——不满意就读档回去换个打法。这个功能已经封装进 app.py（跑完会问"是否回溯改参数重跑"）。

## 四、八个节点，逐个讲"做什么 + 为什么"

| 节点 | 做什么 | 为什么需要它 | 谁干 |
| --- | --- | --- | --- |
| ① parse_intent | LLM 结构化输出，判断分析类型 | 用户说人话，机器要"确定的值"才能路由 | LLM |
| ② load_qc | 读数据 + 质检 + 读长期记忆里的阈值偏好 | 垃圾进垃圾出，数据不合格后面全白算；记忆让阈值"记住上次的选择" | Python |
| ③ human_review | interrupt 暂停，把质检结果抛给用户确认 | 关键步骤要人把关，不能 Agent 闷头跑到底 | 系统 |
| ④ diff_analysis | 真实统计：t 检验 + log2FC + BH 校正，找差异基因 | 分析的核心，必须真算，不能靠 LLM 编数字 | Python |
| ⑤ enrichment | 真实统计：超几何检验 + BH 校正，判断差异基因扎堆在哪些通路 | 光知道"哪些基因变了"不够，还要知道"变了意味着什么功能" | Python |
| ⑥ interpret | LLM 把基因列表 + 富集通路翻译成人话 | 数字要翻译成生物学含义才有价值，这是 LLM 的强项 | LLM |
| ⑦ save_memory | 把本次用的阈值偏好写回长期记忆 | 下次同类分析自动复用，少填参数、越用越顺手 | 系统 |
| ⑧ report | 汇总质检 + 差异 + 富集 + 解读，拼成 Markdown 报告 | 交付物要完整、可保存、可追溯 | Python |

**关键分工思想（面试高频）**：
> **LLM 干"懂"的活，Python 干"算"的活，系统干"把关 + 记忆"的活，各用所长。** 不能让 LLM 去做统计（会算错、会编造），也不能让代码去写自然语言解读。

## 五、两个核心算法，通俗讲清楚

### 算法 1：差异表达分析（判断"哪些基因变了"）

对每个基因，比较 A 组和 B 组的表达量，看三个数：

1. **log2FC（倍数变化）**：表达量差了多少倍。取 log2 是为了让"上调 2 倍"和"下调 2 倍"数值对称（+1 和 -1）。本项目阈值 |log2FC| > 1，即差 2 倍以上。
   - 看的是"**差得多不多**"。

2. **p 值（Welch t 检验）**：这个差异"是不是碰巧出现的"。p 越小越不像碰巧。Welch 版本不假设两组方差相等，更稳健。
   - 看的是"**差得可不可信**"。

3. **FDR（BH 校正）**：一次比成百上千个基因，如果都用 p<0.05，会有一堆假阳性（1000 个基因约 50 个碰巧显著）。BH 校正把"假阳性比例"控制住。
   - 看的是"**一堆判断里有多少是冤枉的**"。

> 一句话：**log2FC 看"差得多不多"，p/FDR 看"差得可不可信"，两个都满足才叫显著。**

### 算法 2：通路富集分析（判断"这些基因扎堆在哪些功能"）

核心是**超几何检验**，生活比喻是"**抽球**"：

- 袋子里有 N 个球（所有基因），其中 K 个是红球（属于某个通路的基因）。
- 你随手抽出 n 个球（显著基因），里面恰好有 k 个红球。
- 如果 k 比"瞎抽该有的数量"多得多，就说明显著基因**偏爱**这个通路 → **富集**。

举个具体例子：假设 100 个基因里只有 10 个属于"细胞周期"通路（K=10），而你找出的 20 个上调基因里居然有 10 个都在"细胞周期"（k=10）。瞎抽的话 20 个里平均才抽到 2 个，现在抽到 10 个，概率极低 → 说明"细胞周期"被显著富集了。

和差异分析一样，一次要查很多通路，所以也要做 **BH 校正**，否则通路一多假阳性跟着多。

> 一句话：**超几何检验回答"显著基因是不是扎堆在某个通路"，扎堆程度远超随机就叫富集。**

## 六、一条请求的完整旅程（面试主线，背这个）

```
用户："帮我找两组样本的差异表达基因，并解读结果"
   ↓
[① parse_intent]  LLM 结构化输出 → analysis_type = "differential"
   ↓
[② load_qc]       读 expression.csv + metadata.csv，自动识别两组
                  质检：文件/分组/样本数/缺失值 → qc_passed = True
                  同时从长期记忆读该用户上次的阈值偏好
   ↓（条件边：合格才继续）
[③ human_review]  interrupt 暂停，把质检结果抛给用户
                  → 用户批准继续 / 取消则走报告结束
   ↓（用户批准）
[④ diff_analysis] 每个基因做 t 检验 + log2FC + BH 校正（用记忆里的阈值）
                  → 找到显著差异基因，分出上调/下调
   ↓
[⑤ enrichment]    对上调、下调基因分别做超几何检验 + BH 校正
                  → 找出显著富集的通路（如"细胞周期""凋亡"）
   ↓
[⑥ interpret]     LLM 读"基因列表 + 富集通路"，解释生物学意义
   ↓
[⑦ save_memory]   把本次的阈值偏好写回长期记忆（下次自动复用）
   ↓
[⑧ report]        汇总质检 + 差异 + 富集 + 解读 → Markdown 报告
   ↓
       END（输出 final_report）
```

**一句话总结整个项目**：
> 我用 LangGraph 把"差异表达分析 + 通路富集"编排成 8 个节点的图，LLM 负责理解和解读、Python 负责质检和统计，中间用条件边做路由、用检查点做断点续跑、用 interrupt 做人工确认、用 Store 做长期记忆，最终自动产出一份可读、带解读的分析报告。

## 九、怎么一步步做出来的（落地顺序，体现工程能力）

1. 先搭骨架：State + 空节点 + 图，跑通"空流程"；
2. 填 diff：写差异分析（纯 Python 统计，先单独测通，不碰 LLM）；
3. 填 enrichment：写富集分析（超几何检验，同样先单独测通）；
4. 接 LLM：parse_intent + interpret 两个节点接上模型；
5. 加质检路由：load_qc 后加条件边；
6. 加检查点：compile 时挂 InMemorySaver（可切 PostgresSaver）；
7. 加人工确认：load_qc 后插 human_review，用 interrupt 暂停；
8. 加长期记忆：save_memory 写 Store，load_qc 读 Store；
9. 出报告：report 节点汇总；
10. 写文档 + 传 GitHub；
11. 加回溯：封装进 app.py，跑完可回历史检查点换阈值重跑；
12. 接真实数据 + 性能优化：TCGA-BRCA（226 样本 × 2 万基因）跑通，diff 向量化（146s→0.15s）、enrichment 用 groupby（→约 7s）。

每一步都能单独验证，不会一步到位卡死。

## 十、如果面试官问"怎么扩展"，怎么答

- **加富集分析**（已实现）：加一个 `enrichment` 节点，在 diff 和 interpret 之间插入一条边，图结构不用大改——这就是"图"的扩展性。
- **加生存分析**：再加一个 `survival` 节点，在 parse_intent 后加一条路由分支。
- **换真实数据**（已实现）：已接入 TCGA-BRCA（226 样本 × 2 万基因），格式和模拟数据一样（表达矩阵 + 分组表），直接替换 `data/` 下的 csv 即可，代码一行不用改。
- **持久化升级**（已实现）：`InMemorySaver` 换成 `PostgresSaver`，检查点从内存搬到数据库，重启不丢；长期记忆同理 `InMemoryStore` → `PostgresStore`。
